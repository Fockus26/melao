# D106 · Auth · La contraseña nueva no puede ser ninguna de las últimas 3: Edge Function change-password + historial en private · Implementado

**Decisión:** restablecer (y, más adelante, cambiar) la contraseña pasa por la Edge Function `change-password`, que rechaza con 422 `password_reused` la actual y las 2 anteriores; luego cambia con `auth.admin.updateUserById`. El historial vive en `private.password_history` (bcrypt de Auth), alimentado por un trigger `after update of encrypted_password` en `auth.users` que guarda el hash anterior y poda a 2. Las tres plataformas usan la función, nunca `updateUser` directo.
**Por qué:** pedido de César (6b). Supabase Auth no tiene historial de contraseñas ni hook para cambios de contraseña; el trigger registra cualquier cambio (función, panel, `updateUser`) sin depender del cliente (D003). Con el hash actual en `auth.users`, guardar 2 basta para "las últimas 3".
**Límite conocido:** `updateUser({ password })` desde un cliente con sesión sigue funcionando (Supabase no deja bloquearlo): quien se salte la app a propósito puede reusar su propia contraseña. El trigger igual lo registra. Residual: la candidata viaja en claro hasta Postgres dentro de la RPC (TLS de PostgREST; no se guarda ni se devuelve).
**Alternativa descartada:** comparar en Deno trayendo los hashes (los expone fuera de la base y suma una librería bcrypt); un Auth Hook (no existe para cambio de contraseña); validar solo en el cliente (rompe D003).
